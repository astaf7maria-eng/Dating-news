# Отбор и рейтинг

Использовать с common.md. Вход: события и подтверждающие статьи, история выпусков, manifest, снимки editorial_policy/pipeline и source_policy из снимка sources.json. Продуктовый контекст Lovito на этапе отбора не передаётся.

1. Проверить допуск по политике и свежести; объединить дубли, сохранив существенные новые стадии/рынки. Неизвестное пометить needs_review. Финансы и маркетинг не требуют продуктового запуска; малые компании требуют новой механики; внешний риск не выдавать за функцию.
2. Оценивать значимость для dating-рынка, disco и биздева по общей задаче дайджеста. Связь с вопросами и планами Lovito не влияет на допуск и оценки. context_assessment оставить null; бизнес-контекст применяется после отбора при написании so what.
3. Оценить критерии из pipeline по 0–5 с основаниями. Итог = сумма(score / 5 × weight) × 100. Новизну оценивать внутри категории; отсутствие подтверждений не компенсировать новизной. При равенстве: качество доказательств, затем более свежая публикация, затем ID по возрастанию.
4. Выбрать глобальный top по лимиту политики без заполнения слабыми событиями; сгруппировать по одному основному разделу. rank — приоритет, display_order — сквозной порядок отображения. Изменение приоритета обосновать отдельно.

Выход: события по event.schema.json и рейтинг всех кандидатов с причинами включения/отклонения. Оценки не требуют контекстных ID, версии или отпечатка Lovito.
