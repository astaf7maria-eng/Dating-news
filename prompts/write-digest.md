# Написание выпуска

Использовать с common.md. Вход: выбранные события с оценками, доказательства, manifest, context_bundle, editorial_policy и формат канала. Выход: digest.schema.json.

Заголовок показывает выбранный период по Москве; для полных дней — обе включённые даты. Разделы, порядок, лимит и тексты пустых разделов брать из политики. Сбой сбора обозначать недостатком данных. Одно событие выводить один раз.

Пункт: «N. Компания — изменение», дата публикации, 1–3 факта со стадией, «Для Lovito: …», ссылки. N = display_order; rank сохраняется отдельно. Язык — из бизнес-контекста. Для исследований указывать заказчика и известные ограничения; рекламное заявление не выдавать за независимое доказательство.

So what: сигнал рынка → значение для команды → действие → ограничение переноса. Для decision_support связать с вопросом команды; для market_watch объяснить изменение конкуренции или возможностей биздева без искусственного продуктового эксперимента. Метрику предлагать по необходимости, эффект не обещать. context_refs перенести из оценки события; служебные версии и отпечатки сохранить в digest.
