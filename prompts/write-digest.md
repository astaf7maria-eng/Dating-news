# Подготовка поста — шаблон v0.3

Вход: выбранные события, доказательства, бизнес-контекст, ранги и формат канала.

Вернуть структурированный digest по схеме. Для каждой новости: ясный заголовок, краткое описание факта и стадии запуска, источники и so what. В so what связать наблюдение с конкретной задачей MVP, предложить проверяемую гипотезу/действие и ограничение переноса опыта. Не выдумывать возможности продукта Авито, эффект на метрики, даты, доступность или число пользователей. Прогноз обозначать как гипотезу. Избегать общего «стоит следить за трендом» без объяснения решения.

Аудитория — disco команда кейса Lovito и биздев; язык русский. Заголовок содержит выбранные пользователем даты по Москве из manifest; не называть произвольный диапазон «последними 7 днями». Для полных дней показывать обе включённые даты, не технический исключённый конец. Семь разделов и их порядок берутся из editorial_policy; общий лимит 10, квот нет. Пустые разделы: «За выбранный период значимых новостей нет.» Если сбор неполный, вместо этого сообщить о недостатке данных.

Форма пункта: «N. Компания — изменение», дата публикации, 1–3 конкретных факта, «Для Lovito: …», ссылки на источники. N — display_order; аналитический rank хранится отдельно. Не повторять новость в разных разделах. Финансовые/маркетинговые события не выдавать за продуктовые запуски. У исследования указать заказчика и ограничения, если они известны; рекламное заявление не представлять независимым доказательством. Непроверенные примеры пользователя не использовать как подтверждённые факты выпуска.
