# Dating News Digest

Еженедельный дайджест российских и международных онлайн-знакомств для disco команды кейса Lovito (MVP знакомств Авито) и биздева.

Это новый независимый каркас проекта. Содержимое родительской папки не использовалось. Сейчас готовы структура, контракты данных, шаблоны настроек и создание запуска; поиск, LLM-обработка и публикация ещё не реализованы.

## Результат одного запуска

До 10 наиболее релевантных уникальных событий за выбранный пользователем период. Для запроса «за последнюю неделю» сначала предлагаются точные границы последних 7 дней с выбором «да/нет»; при «нет» пользователь вводит свои даты. Семь разделов: новые функции, монетизация, доверие и безопасность, AI, малые компании с новой механикой, финансы/сделки/назначения, маркетинг. Последние два раздела включаются и без продуктовой части — это подтверждено пользователем. Для каждого события: что произошло, компания, дата, источник, значение для Lovito и приоритет. В каждом пустом разделе явно указывается отсутствие значимых новостей; ошибки сбора обозначаются отдельно. Общей квоты по разделам нет.

Язык выпуска — русский. Язык и текст источника сохраняются без подмены переводом. Российские и международные события рассматриваются совместно; географические квоты задаются после получения бизнес-контекста.

## Структура

```text
config/                     бизнес-контекст, компании, источники, запросы, параметры
docs/                       архитектура, план реализации, критерии качества
schemas/                    JSON Schema для артефактов между модулями
prompts/                    инструкции для отбора, написания и проверки
src/dating_digest/
  discovery/                1. компании, источники и поисковые запросы
  ingestion/                2. поиск, загрузка, извлечение, нормализация
  editorial/                3. объединение событий, оценка, top-10, so what
  publishing/               4. независимая проверка, рендеринг, доставка
  domain/                   общие модели и правила предметной области
  storage/                  JSON-хранилище и состояние доставки
  orchestration/            запуски, повторы и расписание
data/                       локальные артефакты запусков, исключены из Git
tests/                      будущие содержательные тесты и фикстуры
```

## Быстрый старт каркаса

Python 3.11+, внешние пакеты пока не нужны. Из корня этого проекта в PowerShell:

```powershell
$env:PYTHONPATH = (Join-Path (Get-Location) 'src')
python -m dating_digest --help
python -m dating_digest init-run --as-of 2026-11-15T12:00:00+03:00
# Или сразу передать свой диапазон; оба дня включаются целиком:
python -m dating_digest init-run --start-date 2026-11-01 --end-date 2026-11-14
```

`init-run` сначала спрашивает: «Предлагаю период: 08.11.2026 12:00:00 — 15.11.2026 12:00:00 МСК (конец не включается). Подходит? [да/нет]». При «нет» запрашивает свои даты; они могут задавать период любой длины. Без `--as-of` предложение рассчитывается от текущего времени. Без ответа запуск не создаётся. Явные `--start-date` и `--end-date` считаются выбором пользователя; вводимые даты включают оба полных дня по Москве. В манифесте конец нормализуется до 00:00 следующего дня и не включается. Время через `--as-of` обязательно содержит часовой пояс.

После выбора создаются папка запуска и манифест v0.3 со статусами `planned`, точными границами и способом подтверждения. Сбор и отправка пока не реализованы. Старые манифесты не перезаписываются. Свежий пересказ старого запуска без нового факта отсекается отдельно. Сценарий диалога описан в `prompts/confirm-period.md`. Для запуска по расписанию без диалога потребуется отдельно настроенная пользователем политика периода.

## Что нужно уточнить следующим шагом

- Сценарии MVP, приоритеты disco/биздева и продуктовые ограничения.
- Дополнительные примеры сильных/слабых новостей и обязательные компании.
- День выпуска, необходимость географического баланса, желаемый размер поста.
- Канал доставки: Telegram или Mattermost; целевая группа/канал и режим публикации.
- Доступные поисковые сервисы, модель и ограничения затрат.

Аудитория и тематика внесены в `config/business_context.json`; редакционная политика — в `config/editorial_policy.json`. Пользовательские примеры и их разбор хранятся только локально в `docs/examples/` и не публикуются в Git. Компании и источники из примеров — пока непроверенные кандидаты; российское покрытие ещё предстоит исследовать. Рейтинг остаётся предварительным до уточнения продуктовых приоритетов. Секреты не хранятся в JSON; имена переменных перечислены в `.env.example`.

В репозиторий включаются код, тесты, конфиги, схемы, промпты и основные документы. `data/`, пользовательские примеры, секреты, кэши, журналы и временные файлы исключены через `.gitignore`.
