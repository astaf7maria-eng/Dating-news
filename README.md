# Dating News Digest

Дайджест российских и международных онлайн-знакомств для disco-команды Lovito и биздева. Целевой результат — до 10 уникальных событий на русском с источниками, приоритетом и значением для команды; разделы и правила заданы в [редакционной политике](config/editorial_policy.json).

**Работает:** выбор периода, фиксация конфигов и построение поискового плана. Поиск, загрузка статей, LLM-редактура, проверка выпуска и доставка ещё не реализованы.

## Контекст Lovito: 10 ключевых so what для дайджеста

Исходный документ: [Avito Dating / Lovito — Gate 2](docs/context/Avito_Dating_Lovito_Gate2.pdf). Копия PDF находится в `docs/context/`. Ниже — выводы для работы дайджеста на основе Gate 2 от 18.08.2026. Это фиксированный контекст, предоставленный пользователем для более глубоких so what по уже найденным и отобранным новостям. Проверять актуальность, исследовать или изменять PDF и business_context.json не требуется.

1. **Оценивать пользу для безопасных серьёзных знакомств.** Для продуктовой новости объяснять, какой вопрос Lovito она помогает решить; для бизнес-новости — что меняется в конкурентной ситуации или возможностях биздева. Основание: стр. 2–3.

2. **Учитывать женскую аудиторию и баланс площадки.** В Gate 2 женщины 25–44 лет выделены как ключевая аудитория. В новостях о привлечении и удержании искать эффект на эту аудиторию и достаточность подходящих анкет, сохраняя мониторинг других сегментов. Основание: стр. 3, 6.

3. **Искать конкретные механики безопасности.** Верификация, антифрод, жалобы, модерация и защита чатов полезны как самостоятельные темы. Особенно ценны данные об эффективности, ошибках, стоимости и времени реакции. Основание: стр. 4–5, 9.

4. **Разбирать проверки вместе с потерями воронки.** Fake-door выявил риск оттока на шаге верификации. Искать способы выбора момента и глубины проверки; результат fake-door не выдавать за конверсию реальной проверки личности или liveness. Основание: стр. 4–5, 14.

5. **Оценивать экосистемные механики вместе с приватностью.** В плане предусмотрен отдельный dating-профиль внутри Авито. Для интеграций и доверительных сигналов объяснять, какие данные необходимы и какие риски раскрытия они создают. Основание: стр. 3, 5–6.

6. **Смотреть на качество диалога и переход к встрече.** Лайки на фрагменты анкеты, ограничения активных диалогов и другие механики оценивать через содержательное общение и реальные встречи, а не только рост активности в ленте. Основание: стр. 5, 9.

7. **Извлекать из маркетинга уроки локального запуска.** Для городского пилота важны предварительное наполнение базы, привлечение женщин и экономика каналов. География пилота не ограничивает страны и города, новости которых попадают в дайджест. Основание: стр. 6, 8.

8. **Сопоставлять монетизацию с доверием и удержанием.** В новостях о подписках, тарифах и платном продвижении изучать состав предложения, готовность платить и последствия ограничений; прогнозы Gate 2 сохранять как гипотезы. Основание: стр. 5–8.

9. **Различать близкое и перспективное применение AI.** Для модерации, ранжирования и ассистентов указывать задачу, зрелость, требования к данным и измеряемый результат. Будущие механики сохранять в мониторинге, даже если они не относятся к первому этапу Lovito. Основание: стр. 5–6.

10. **Объяснять конкретное значение новости.** По смыслу добавлять, что команде стоит изучить, сравнить, проверить или отслеживать, и существенные ограничения переносимости опыта. Различать активность Lovito и дополнительную активность Авито, прямую выручку и гипотезы межвертикального эффекта. Основание: стр. 4, 6, 8–9, 15.

Машинная версия контекста — [business_context.json](config/business_context.json): утверждения со статусами и страницами, семь вопросов команды. Сохранённые в файле поисковые поля не используются для генерации запросов. Применение исключительно в so what описано в [интеграции контекста](docs/context-integration.md). В документе расходятся сроки решения о масштабировании (стр. 3 и 9) и ограничения фото/звонков (стр. 5–6); эти детали не используются как однозначные актуальные факты.

## Запуск

Python 3.11+, внешние пакеты не нужны. PowerShell из корня проекта:

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
$env:PYTHONIOENCODING = 'utf-8'
python -m dating_digest --help
python -m dating_digest init-run --start-date 2026-11-01 --end-date 2026-11-14
# Подставить путь созданного запуска:
python -m dating_digest plan-search --run-dir data/runs/<run_id>
python -m unittest discover -s tests -v
```

Обе даты включаются целиком по Москве. Альтернатива: `init-run --as-of 2026-11-15T12:00:00+03:00` предложит последние 7 дней и запросит «да/нет»; при отказе — свои даты. Без ответа запуск не создаётся. В артефактах окно хранится как `[window_start, window_end_exclusive)`.

`init-run` создаёт манифест v0.5, `context_bundle.json` и снимки семи конфигов в `config_snapshot/`. `plan-search` читает только эти снимки, сверяет SHA-256 и сохраняет `search_plan.json` v0.9 с запросами и ожидаемым покрытием. План не означает выполненный поиск. Повторная запись запрещена. Для старых манифестов v0.3/v0.4 используется текущий каталог с явным предупреждением; для полностью воспроизводимого запуска создайте новый. `--config-dir` выбирает настройки при создании запуска и каталог для старых запусков.

`queries` сохраняют отдельные цели покрытия, а `search_tasks` объединяют одинаковый текст с привязкой всех query_id к языковым вариантам. С текущим каталогом это 338 целей, 321 задание и 338 отдельных языковых обращений до оптимизации провайдером. RU/EN остаются обязательными: один многоязычный запрос допустим лишь при поддержке всех языков провайдером. Совпадение текста не позволяет переиспользовать результат с другими фильтрами, периодом или страницей. Экономия сетевых вызовов пока не измерена; одинаковые текст и язык для нескольких целей требуют одного обращения с общим результатом.

Порядок поиска: официальные страницы для медиа/инвесторов → остальные официальные источники → ключевые СМИ по ключевым словам → широкий поиск. Список СМИ, ключевые слова и правила выбора доказательств по типу утверждения — в `source_policy` файла `config/sources.json`. Найденное официальное сообщение не отменяет проверку СМИ.

Перед созданием запуска и планированием проверяются ссылки каталогов, обязательные компании, разделы, лимит и веса рейтинга по схемам. JSON публикуется атомарно после полной записи через hard link на том же диске; существующий файл не заменяется. Нужна файловая система с поддержкой hard links (например, NTFS); при ошибке записи итоговый файл не создаётся.

## Где менять правила

| Данные | Источник |
| --- | --- |
| Аудитория, язык, утверждения Gate 2 и вопросы команды | [business_context.json](config/business_context.json) |
| Разделы, допуск, лимит выпуска и so what | [editorial_policy.json](config/editorial_policy.json) |
| Период, веса, параметры интеграций | [pipeline.json](config/pipeline.json) |
| Обязательные компании, источники и поисковые фразы | [companies.json](config/companies.json), [sources.json](config/sources.json), [queries.json](config/queries.json) |
| Исторические примеры покрытия | [golden_set.json](config/golden_set.json) |
| Форматы артефактов | `schemas/` |

Код находится в `src/dating_digest/`: `domain` — период и контекст, `discovery` — план запросов, `orchestration` — диалог выбора периода. Общие инструкции будущих LLM-вызовов — `prompts/common.md`; к ним добавляется только промпт текущего этапа.

Контекст Gate 2 используется только для so what по уже отобранным новостям. Он не создаёт запросы, не меняет допуск и рейтинг; проверка или актуализация самого контекста не входят в процесс дайджеста. Подробности и оценка качества выводов — [интеграция контекста](docs/context-integration.md).

Локальные `data/`, примеры, секреты и временные файлы исключены из Git. Исходный PDF сохранён в `docs/context/` и доступен для включения в репозиторий; для запуска он необязателен. Переменные интеграций перечислены в [.env.example](.env.example).
