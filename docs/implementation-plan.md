# План реализации

Готовы выбор периода, снимки запуска, поисковый план, общий обработчик сохранённого HTML, постоянный архив и [QA исследования](research-qa.md) после сохранения корпуса. Рабочий маршрут — в README; ручной сбор — по prompts/collect-news-fast.md, сверка источников — по review-research.md. Каталог и golden set заполнены; полнота реального поиска и качество рейтинга ещё не измерены.

Контекст Lovito предоставлен пользователем один раз и используется исключительно для более глубоких so what по найденным и отобранным новостям. Проверять актуальность, исследовать или менять PDF и business_context.json не требуется; это не этап и не условие запуска.

1. Подключить поставщика поиска и сетевой загрузчик к готовому `ingestion.extract_article`; сохранить корпус и фактическое покрытие, проверить исторический golden set отдельно от live-периода. Для новых шаблонов сайтов расширять общий обработчик, а не сессионные копии.
2. Разметить редакционный эталон на собранном корпусе для оценки качества отбора и so what; это проверка качества дайджеста, а не контекста Lovito.
3. Реализовать объединение событий, допуск и рейтинг по общей задаче дайджеста; затем написать выпуск, используя контекст Lovito только в so what. Сопоставить с эталоном.
4. Расширить исполнение JSON Schema и перекрёстных проверок на Event/Digest/финальный Review, затем подключить независимую LLM-рецензию с ограниченным циклом исправлений. Схемы Article и research-review уже исполняются в постархивной QA; сверка источников пока сессионная.
5. Реализовать выбранный канал, экранирование/разбиение и журнал доставки; проверить частичный сбой и неоднозначный ответ API.
6. Настроить возобновление, секреты, журналы и расписание с явно выбранной политикой периода.

Решения для подключения интеграций: поставщики поиска/LLM и бюджет, хост исполнения, канал/адресат и режим доставки, время выпуска, пределы длины и порог достаточного покрытия. Канал и расписание ранее отложены пользователем. Новые зависимости добавлять под выбранную интеграцию.
