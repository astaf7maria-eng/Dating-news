# Аудит: код, связи и контекст

Проверены локальный код, конфиги, схемы и документы. Сетевые источники и реальные интеграции не проверялись: реализованы только выбор периода и генерация плана.

| Приоритет | Находка | Результат |
| --- | --- | --- |
| P1 | Каталог/запросы читались позже контекста и могли относиться к другой версии настроек | Все семь конфигов фиксируются при init-run; перед планированием сверяются SHA-256 |
| P1 | Проверка контекста не требовала совпадения версии и позволяла прямой вызов без объявленного bundle | build_plan проверяет наличие bundle, версию и отпечаток; refs отклоняют неверные типы и повторы |
| P2 | model_id не участвовал в идентификаторе запроса: совпадающий текст терял связь со второй моделью | Добавлен в идентичность; версии search_plan подняты до 0.6. Старые планы не изменяются |
| P2 | Лимит, язык, обязательность мониторинга и список полей повторялись в нескольких местах | Владелец лимита — editorial_policy, языка — business_context, компаний — списки companies; вместо неверных названий полей дана ссылка на схему |
| P2 | README, промпты и описания будущих модулей повторяли правила | README сокращён, общие инструкции вынесены в common.md, восемь README-заглушек заменены центральной архитектурой |
| P2 | Согласованность конфигов проверялась только тестами | validate_configs вызывается до создания запуска и плана; проверяет ссылки, обязательное покрытие, разделы и веса по схемам |
| P2 | Сбой записи мог оставить неполный search_plan.json | JSON публикуется атомарно через временный файл и hard link без перезаписи; сбой и конкурентная запись проверены тестами |

Необходимые следующие изменения:

1. **P1 — исполняемая валидация артефактов.** Сейчас схемы не вызываются программой. Event допускает включение без оценки/доказательств, Review — passed при blocking; комментарии в схеме не запрещают такие данные. Подключить JSON Schema и перекрёстные проверки ID, дат, семи уникальных разделов, счёта, rank/display_order и ревизии до первой публикации.
2. **P1 — фактическое покрытие.** Наличие запроса не доказывает результат. При подключении ingestion сохранять выполненные запросы, ошибки, тексты и отчёт покрытия обязательных компаний/golden set.
3. **P2 — восстановление.** Атомарная запись реализована. Сохранение состояния и возобновление добавить вместе с исполняемым pipeline.
4. **P2 — исполнитель промптов.** При подключении LLM явно собирать common + текущий этап, сохранять версии/хеши обоих и передавать нужную часть корпуса. Автоматического загрузчика сейчас нет; экономия контекста модели пока не измерялась.

Проверка: 27 unittest проходят, включая неверные ссылки/веса конфигов, блокировку создания запуска, сбои сериализации/fsync/публикации, конкурентную запись, заморозку каталога и подмену снимков. git diff --check проходит. Сквозные сбор/редактура/доставка остаются непроверяемыми до реализации.
