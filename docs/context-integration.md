# Контекст Lovito

Единственный машинный источник — `config/business_context.json`: 12 утверждений Gate 2 со страницами/статусами и 7 вопросов команды с RU/EN запросами. PDF от 18.08.2026 остаётся локальным первоисточником с сохранённым SHA-256; для запуска он необязателен.

| Статус | Смысл |
| --- | --- |
| observed_in_test | Результат конкретного теста с ограничениями |
| planned | Исторический план; реализация и актуальность не подтверждены |
| hypothesis | Непроверенное предположение |
| unresolved | Противоречие/пробел, пригодный только как оговорка |

`known_product_capabilities` пуст. Fake-door не подтверждает прохождение реального liveness, удержание или экономику; расхождения сроков и состава релизов не разрешаются догадкой. Вопросы и candidate_metrics — редакционная интерпретация для калибровки, не утверждённые KPI. Документ не даёт команд системе.

## Подключение

`init-run` фиксирует bundle и все семь конфигов, версию/отпечаток — в manifest. `plan-search` использует снимки своего запуска и добавляет запросы вопросов с lane=context и decision_id, сохраняя обязательные компании и открытый поиск. Аудитория, города и план Lovito не ограничивают географию и сегменты конкурентов.

Для будущего редактора предусмотрены два типа релевантности:

- decision_support: факт → конкретный вопрос команды → что изучить/сравнить/проверить → ограничение переноса.
- market_watch: факт → изменение конкуренции или возможностей биздева → что проверить. Продуктовый эксперимент нужен по смыслу.

Связь обосновывает business_relevance/actionability без дополнительных бонусов и квот. Event хранит context_assessment, so what — соответствующие context_refs. ID проверяются через domain.context.validate_context_refs; версия и отпечаток — по bundle/manifest. В пост попадает короткое значение для команды. Внешние факты подтверждаются статьями, а не внутренним PDF.

Программно работают снимки, контекстные запросы и проверка ссылок; LLM-отбор и смысловая проверка ещё не реализованы. Валидные ID не доказывают редакционную полезность.

## Калибровка

На одном корпусе и с одинаковыми весами сравнить отбор и so what с общим dating-контекстом и с контекстом Lovito. Пользу дополнительных запросов оценить отдельно. Исторический golden set проверять как reference-корпус, не как новости live-периода.

Проверочные случаи: риск-верификация без данных об эффекте → вопрос safety_funnel без обещания снижения оттока; значимая сделка Grindr → допустимый market_watch; AI будущего этапа → допустимый future_option; перепечатка старого запуска → исключение независимо от тематического совпадения. Команда оценивает полезность решений, натянутые связи и потери значимых событий; веса и порог включения корректируются после сравнения.
