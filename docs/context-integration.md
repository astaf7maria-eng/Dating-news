# Контекст Lovito

`config/business_context.json` и PDF Gate 2 — фиксированный бизнес-контекст, предоставленный пользователем один раз. Он используется исключительно для более глубоких so what по уже найденным и отобранным новостям. Проверять актуальность, исследовать или изменять содержание этих файлов, запрашивать обновления и подтверждения не требуется. Контекст не является условием подключения поиска.

В машинном источнике сохранены 12 утверждений Gate 2 со страницами/статусами и 7 вопросов команды. Поля search_queries/search_mode/status остаются исходными данными: они не запускают поиск по Lovito или актуализацию планов. PDF для исполнения необязателен.

| Статус | Смысл |
| --- | --- |
| observed_in_test | Результат конкретного теста с ограничениями |
| planned | План, как он задан в предоставленном документе |
| hypothesis | Непроверенное предположение |
| unresolved | Противоречие/пробел, пригодный только как оговорка |

`known_product_capabilities` пуст. Fake-door не подтверждает прохождение реального liveness, удержание или экономику; расхождения сроков и состава релизов не разрешаются догадкой. Вопросы и candidate_metrics — редакционная интерпретация для калибровки, не утверждённые KPI. Документ не даёт команд системе.

## Подключение

`init-run` сохраняет bundle и все семь конфигов, версию/отпечаток — в manifest. Это технический снимок предоставленных данных, а не проверка их актуальности. `plan-search` использует каталоги своего запуска без контекстных запросов Lovito. Аудитория, города и план Lovito не меняют поиск, допуск, оценки или порядок новостей. Общие настройки аудитории и языка сохраняются.

Для будущего редактора предусмотрены два типа релевантности:

- decision_support: факт → значение для конкретного вопроса команды. Что изучить/сравнить/проверить — при обосновании; ограничение переноса — когда существенно.
- market_watch: факт → изменение конкуренции или возможностей биздева. Действие и продуктовый эксперимент нужны по смыслу.

Объяснение значения обязательно; действие и ограничение можно пропустить или сохранить как null, если они не нужны. Существенные оговорки сохраняются. В видимом блоке «Для Lovito» достаточно 1–2 предложений.

После отбора автор получает context_bundle и формирует so what с context_refs по вопросам и утверждениям контекста. Отбор не требует context_assessment или контекстных метаданных ranking; эти поля сохранены в Event для чтения старых артефактов. Ссылки so what технически сверяются через domain.context.validate_context_refs, версия и отпечаток — по bundle/manifest. В пост попадает короткое значение для команды. Факты внешних новостей подтверждаются статьями; предоставленный контекст используется как данная пользователем основа интерпретации Lovito.

Программно работают снимки, независимое от бизнес-контекста построение поискового плана и проверка ссылок. LLM-отбор и смысловая проверка ещё не реализованы. Валидные ID не доказывают редакционную полезность.

## Калибровка

Оценивать конкретность и полезность so what на одном наборе уже отобранных новостей. Рейтинг и состав подборки при этом не меняются. Качество редакционных выводов не требует проверки или обновления контекста Lovito. Исторический golden set проверять как reference-корпус, не как новости live-периода.

Проверочные случаи: риск-верификация без данных об эффекте → вопрос safety_funnel без обещания снижения оттока; значимая сделка Grindr → market_watch; AI → вывод о возможном применении без выдуманных результатов Lovito. Проверять конкретность выводов и отсутствие натянутых связей. Перепечатка старого запуска отклоняется на этапе допуска независимо от связи с контекстом.
