# Проверка исследования после сохранения JSON

Между `archive-articles` и `select-and-rank` добавлена отдельная QA. Финальная `review-digest` проверяет уже написанный выпуск и остаётся обязательной. Сбор и QA выполняются в сессии: CLI не вызывает сеть/LLM.

## Рабочий маршрут

1. Сохранить все подходящие статьи, краткие события, причины исключений и фактические журналы; выполнить archive-articles.
2. `python -m dating_digest qa-research --run-dir data/runs/<run_id>` сохраняет `research_audit.json`. Код 1 означает blocking; код 0 — только успешные локальные проверки, смысловая QA ещё не выполнена.
3. Выполнить common.md + [review-research.md](../prompts/review-research.md). Проверить каждый Article, две таблицы покрытия и семь направлений QA. По источникам проверить факты, дату и новизну, целостность извлечения, допуск и события. Сделать контрольный поиск по конкретным пробелам и трём основным направлениям. Сохранить наблюдения в raw/research_verification.jsonl, обращения — raw/qa_search_log.jsonl. Обнаруженные подходящие материалы добавить обычным маршрутом; архив не переписывать.
4. После последней записи входных данных повторить qa-research и сформировать `research_review.json` по новой [схеме](../schemas/research-review.schema.json). Отчёт создаёт рецензент; CLI не генерирует прошедший review и не заполняет доказательства.
5. `python -m dating_digest check-research-qa --run-dir data/runs/<run_id>` проверяет отчёт и возвращает eligible_article_paths. Перед отбором выполнять команду заново; использовать только эти статьи. При ошибке продолжать QA, при исчерпанном бюджете сохранить needs_revision и очередь.

## Что проверяет код

`src/dating_digest/research_qa.py` исполняет Article JSON Schema с проверкой форматов для **всех** articles/*.json и уникальных архивных файлов из квитанции запуска. Проверяются UTF-8/JSON/JSONL, SHA-256 текста, HTTP(S) URL, связи квитанции, наличие архивных тел, ID, целостность снимков и соответствие окна плану. Статьи не изменяются, весь исторический архив не сканируется. Некорректная структура критических артефактов может завершить команду ошибкой до сохранения отчёта.

Неизвестная/внеоконная дата, частичная дневная граница, неполный текст, повреждённая кодировка и диагностика извлечения запрещают eligible, пока карточка не исправлена. Такие статьи можно явно исключить. Прочие замечания о тегах/возможных дублях требуют оценки рецензента. Структурные ошибки блокируют переход независимо от исключения статьи; исправлять через staging и новую архивную версию, не править старые файлы напрямую. ArticleArchive.save и archive-articles проверяют схему до записи; исправления проверяемых метаданных создают версии. Исторические тела сохраняются.

Отпечаток включает manifest, план, снимки, подготовленные статьи, квитанцию/индекс, все файлы raw/, связанные архивные тела, правила common/review-research, схемы и код QA. research_audit/research_review не входят в собственный отпечаток. Отчёт должен относиться к текущему набору файлов; добавление/удаление/изменение входа инвалидирует результат. Изменение несвязанных исторических статей не требует повторной QA данного запуска.

Gate исполняет схему research-review, запрещает passed с blocking, требует все семь завершённых проверок, ровно одну оценку каждого Article и каждой ячейки из плана. error/not_checked и needs_review не проходят. evidence_refs должны указывать существующие строки raw/*.jsonl с наблюдением источника/поиска; допускаются только checked/completed/assessed/no_results/empty. Наблюдения незавершённых проверок и batch_union_not_per_query отклоняются. Для статьи нужен article_id, для покрытия — target или targets; совпадение бренда в запросе не заменяет явную оценку. Противоречащие eligible результаты наблюдений блокируют допуск. **Соответствие цитаты факту, полнота охвата периода и достоверность итогового вывода остаются смысловой проверкой**; наличие строки журнала не доказывает их автоматически. Программная проверка не заменяет рецензента.

Для нового сбора 1–15 ноября 2026 создавать новый init-run с явными датами `--start-date 2026-11-01 --end-date 2026-11-15`. Снимки старого запуска без research_policy/search_intents/external_search не поддерживают нынешний маршрут; они не изменяются автоматически. В локальном контроле 16.11.2026 все 11 доступных Article JSON архива/staging прошли схему с проверкой форматов. Это проверка совместимости структуры, не дат, содержания или полноты прежнего сбора.

Из образца MI перенесены покрытие, даты, качество источников, фильтры, формат/смысл и проверочный поиск. Адаптация dating сохраняет приоритет официальных первоисточников, локальные языки, интервью/новые раскрытия, допустимость финансов/рисков/маркетинга и пустых тем. Контекст Lovito не используется для допуска и не перепроверяется. Квота публикаций или полный обход всех тем не вводятся. QA имеет отдельное время и число запросов; успех локальных тестов не доказывает полноту живого исследования.
