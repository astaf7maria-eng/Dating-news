# Обработка сохранённых страниц

Рабочий маршрут: поиск и загрузка инструментами сессии → сохранённый HTML → общий обработчик → проверка агентом → существующий архив. Загрузчик и автономный поисковый исполнитель этой командой не добавляются.

## Вход и запуск

Установка из корня проекта: `python -m pip install -e .`. В `raw/pages/<id>.metadata.json` агент сохраняет проверенные метаданные, например:

```json
{
  "url": "https://example.com/news/verified-profiles",
  "source_id": "example_newsroom",
  "company_ids": [],
  "published_at": null,
  "date_precision": "unknown",
  "event_date": null,
  "collected_at": "2026-11-16T09:00:00+00:00"
}
```

Если дата известна, нужны `published_at`, `date_precision` и исходная календарная дата `published_date_raw`; доказательство можно сохранить в `date_evidence`. Обработчик сохраняет переданную дату и не берёт случайный `<time>` из комментариев или соседней новости. Неизвестная дата остаётся неизвестной. Можно передать существующий `article_id` и другие поля Article.

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
$env:PYTHONIOENCODING = 'utf-8'
python -m dating_digest extract-page --html data/runs/<run_id>/raw/pages/<id>.html --metadata data/runs/<run_id>/raw/pages/<id>.metadata.json --output data/runs/<run_id>/articles/<id>.json --tags features trust_safety
python -m dating_digest archive-articles --run-dir data/runs/<run_id>
```

HTML и JSON читать/писать в UTF-8. В Python тот же путь: `from dating_digest.ingestion import extract_article`, затем `extract_article(html, metadata, tags=["features", "trust_safety"])`. Модуль не запускает сеть и не читает старую сессионную очередь при импорте. Выход создаётся без перезаписи существующего файла.

## Заголовок и текст

Заголовок выбирается по Article JSON-LD, og:title, twitter:title, H1 и HTML title. Учитываются совпадения, соответствие URL, название сайта и обрезанные заголовки. Первый H1 с логотипом больше не получает безусловный приоритет.

Обработчик удаляет известные рекламные и рекомендательные виджеты, комментарии, навигацию и боковые блоки. Название класса проверяется целиком: слово sidebar в названии общей сетки не удаляет её содержимое. Сохраняются цитаты, списки, таблицы, ограничения и завершающие абзацы. Повторные абзацы мобильной/десктопной версии удаляются по нормализованному тексту; уникальные условия остаются. Выбор компактного контейнера тоже позволяет избежать повторной версии статьи.

Сравниваются содержимое нескольких кандидатов и доля ссылок; первый подходящий CSS-селектор не завершает извлечение автоматически. Основная статья имеет приоритет перед общей оболочкой с навигацией. Есть поддержка безымянных контейнеров и articleBody из JSON-LD.

`extraction_status` зависит от содержимого: слишком короткий текст, признаки обрезки/платного доступа, высокая доля ссылок, повреждённая кодировка и отсутствие заголовка требуют проверки. Если выбран специальный контейнер, а в более широком блоке остались содержательные абзацы, выставляется partial с причиной `additional_substantive_text_outside_container`; число таких абзацев доступно в `unselected_paragraph_count`. Это может быть как пропущенное условие, так и повторный FAQ или авторский блок: агент сверяет их и подтверждает полноту либо дополняет извлечение. Причины записываются в `extraction_diagnostics.quality_issues` и `extraction_error`; источник заголовка и число удалённых повторных символов также доступны. Короткая законченная новость может получить full без специального селектора; текст внутри .article-body может остаться partial. При выборе компактной версии проверяется сохранение уникальных блоков, включая короткие условия вроде «только Япония».

Эвристики не гарантируют полноту произвольного сайта. Агент сверяет содержательные разделы, числа, условия и оговорки с источником. Если полную статью получить не удалось, сохраняется partial с причиной. Шаблон, для которого очистка пропускает виджет или часть статьи, требует отдельного исправления общего обработчика. Поиск не выполняется повторно только из-за нового тематического тега.

## Формат и границы изменения

Article хранит заголовок, URL, исходный текст и тематические `tags`: features, monetization, trust_safety, ai, new_models, business, marketing. Теги выбирает агент по смыслу; модуль проверяет допустимые значения. Возможны несколько тегов. Старые Article без tags остаются совместимыми со схемой 0.1. Технические поля архива сохраняются; поле типа страницы не вводится. Русский пересказ относится к редактуре, исходный текст не переводится и не исправляется молча при повреждённой кодировке.

Объединение источников одного события этим изменением не реализовано. Все Article остаются отдельными доказательствами. Будущая общая карточка события сможет ссылаться на несколько статей; отдельные кампании и существенные этапы доступа потребуют раздельной редакционной оценки.

## 4. Язык исходника и карточки события

**Исходную статью хранить на языке оригинала, русскую карточку события формировать при смысловой обработке. UTF-8 использовать на обоих этапах.**

`extract-page` сохраняет исходные `Article.title`, `Article.text` и язык статьи. При анализе по `prompts/analyze-news.md` агент создаёт отдельный Event в `events/` запуска: `headline` и `facts[].claim` по-русски, с сохранением чисел, условий, стадий и оговорок. `facts[].evidence_quote` остаётся точной цитатой на языке источника и связывается с ним через `article_id`. Названия компаний/продуктов, URL и служебные ID не переводятся. Русская карточка не подменяет исходный Article и не меняет его хеш.

Оба JSON читаются/пишутся через `dating_digest.io.read_json/write_json`: явная кодировка UTF-8, сохранение символов без ASCII-экранирования; чтение допускает UTF-8 BOM. Для финального Article используется общий архив с этим же JSON I/O. HTML-обработчик не выполняет перевод; смысловой этап пока выполняется агентом по промпту.

## Локальная проверка на корпусе 1–14 ноября 2026

Повторно обработаны 49 сохранённых HTML без сети и без изменения архивных Article. Это проверка извлечения, а не новый поиск или оценка допуска новостей. Автоматически full получили 36 страниц, partial — 13: CMB с уже повреждённой кодировкой в исходном кэше, страница-указатель GDI с анонсом вместо полной статьи и 11 страниц с содержательными блоками вне выбранного контейнера. Последние требуют сверки: среди внешних блоков есть вводные описания, FAQ и служебный текст; сам факт их наличия не доказывает потерю статьи. Частичный статус намеренно не повышается автоматически по известному CSS-селектору. Сравнения из корпуса по-прежнему исключаются редакционными правилами независимо от качества их текста.

Автотесты проверяют также списки условий, таблицы, цитаты, короткую законченную новость, обрезку в специальном CSS-контейнере, уникальные условия в адаптивной версии, сохранение языка/метаданных и маршрут CLI → архив. Числа относятся к сохранённому корпусу, не гарантируют результат на новой разметке сайта.
