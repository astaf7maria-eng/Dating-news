# Постоянный архив статей

Основное хранилище находится в `article/` в корне проекта и используется всеми запусками:

```text
article/
  2026/
    11/
      02.11.26/
        <article_id>.json
      03.11.26/
        <article_id>.json
  _undated/
    <article_id>.json
  .archive.sqlite3
```

Папка берётся из календарной даты `published_date_raw`. Если исходная дата отсутствует или не распознана, используется проверенная `published_at` по Москве. Исходные поля в JSON сохраняются. `date_precision: unknown` всегда направляет карточку в `_undated`: дата загрузки или события не подменяет дату публикации. Пустые дневные папки заранее не создаются.

## Как сохранять

Команда для подготовленных карточек конкретного запуска:

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
$env:PYTHONIOENCODING = 'utf-8'
python -m dating_digest archive-articles --run-dir data/runs/<run_id>
```

Она читает `articles/*.json` запуска и сохраняет итоговые статьи в общий архив. `article_archive.json` содержит результаты `created`, `duplicate`, `new_version`, связи с URL и относительные ссылки на архив. В существующем `article_index.json` добавляются архивные ссылки. Прежние карточки запуска остаются снимком для совместимости с историческим отчётом; новый запуск не очищает их и общий архив.

Коллектор, сохраняющий по одной статье, должен использовать тот же механизм:

```python
from dating_digest.storage import ArticleArchive

archive = ArticleArchive("article")
result = archive.save(article, run_id=run_id, source_path=source_path)
```

Окончательное сохранение выполняется через этот API или CLI, а не через прямой `write_text` в архив. В разовом сценарии `.tmp/finish_collection.py` архивирование вызывается после нормализации и проверки корпуса. Основной автономный поиск ещё не реализован.

Путь по умолчанию задан в `config/pipeline.json → storage.article_archive_dir`. Новые `init-run` фиксируют его в `manifest.article_storage`, поэтому запуск не получает отдельный очищаемый архив. `--archive-dir` позволяет выбрать другой постоянный каталог; размещение внутри папки отдельного запуска запрещено.

## Проверка дублей и версий

1. `article_id` и нормализованные исходный/canonical URL ищутся по постоянному индексу.
2. Сравнивается SHA-256 нормализованного текста: Unicode NFC, объединение пробельных символов. Исходный текст и его точный `text_sha256` остаются в JSON. Пустые тексты разных статей не объединяются.
3. Одинаковая карточка в следующем запуске получает `duplicate`; существующий JSON не перезаписывается. Изменение только времени загрузки или query ID не создаёт новую версию.
4. Одинаковый текст на другом URL хранится один раз. Дополнительные ID, URL, источник, метаданные и связь с запуском записываются в индекс наблюдений. Повторная публикация не объявляется независимым подтверждением.
5. Новый текст, изменённый заголовок, подтверждённая дата или статус извлечения для известной статьи создают отдельную версию `<article_id>__<fingerprint>.json`. Прежняя версия сохраняется. Уточнение неизвестной даты может создать версию в датированной папке, сохранив первоначальную в `_undated`.
6. Если повторная загрузка известной статьи не дала текста, ранее сохранённый текст остаётся доступен; ошибка сохраняется как наблюдение.

Из URL удаляются fragment и известные tracking-параметры. Значимые параметры, регистр пути и разные домены не объединяются догадкой. Это дедупликация документов, а не объединение нескольких статей в одно событие.

## Сохранность и Git

Тела статей публикуются атомарно без перезаписи существующего файла. SQLite-транзакция сериализует конкурентные сохранения. Повтор после ошибки индекса может подхватить уже записанный JSON, а при утрате пустого/отсутствующего каталога индекс восстанавливает основные ID/URL по файлам. Дополнительные наблюдения других источников хранятся именно в `.archive.sqlite3`, поэтому он является частью постоянных локальных данных, а не временным кэшем.

`article/`, `data/` и `.tmp/` исключены из Git. В репозиторий входят код, настройки, тесты и документация; корпус, локальный индекс и результаты запусков не добавляются. Изменения проверяются тестами на разные прогоны, дубли URL/текста, версии, неизвестные даты, конкурентную запись и сбой между записью JSON и обновлением индекса.
