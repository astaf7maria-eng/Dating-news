# Постоянный архив

`article/YYYY/MM/DD.MM.YY/<article_id>.json` общий для всех запусков. Дата — календарный день `published_date_raw`, иначе проверенная `published_at` по Москве; исходные поля сохраняются. `date_precision: unknown` всегда даёт `_undated`, дата события/сбора не подставляется. Пустые дни заранее не создаются.

Из корня проекта после подготовки `data/runs/<run_id>/articles/*.json`:

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
python -m dating_digest archive-articles --run-dir data/runs/<run_id>
```

Для поштучного сохранения коллектор вызывает `ArticleArchive("article").save(article, run_id=run_id, source_path=source_path)` из `dating_digest.storage`. Прямая запись в архив не используется; разовый `.tmp/finish_collection.py` вызывает API после проверки корпуса. Автономного поиска пока нет.

| Ситуация | Результат |
|---|---|
| Известный ID или исходный/canonical URL, карточка не изменилась | `duplicate`, JSON переиспользуется |
| Такой же текст на другом URL | Один текст; все дополнительные ID, источники, метаданные и прогоны остаются в SQLite |
| Изменились текст, заголовок, дата или статус извлечения | `new_version`: `<article_id>__<fingerprint>.json`; прежняя версия остаётся |
| Уточнена неизвестная дата | Датированная версия рядом с сохранённым оригиналом в `_undated` |
| Повтор не дал текста | Сохранённый текст остаётся, неудача фиксируется как наблюдение |
| Разные статьи без текста | Не объединяются по пустому хешу |

Сравнение текста использует NFC и объединение пробелов; оригинал и точный SHA-256 не меняются. Из URL удаляются fragment и известные tracking-параметры, значимые параметры/регистр пути/разные домены сохраняются. Время загрузки и query ID не создают версии. Дедупликация документов не заменяет объединение событий, перепечатки не становятся независимым подтверждением.

`pipeline.storage.article_archive_dir` задаёт путь, `manifest.article_storage` фиксирует его. `--archive-dir` может выбрать другой общий каталог; каталог архива и папка отдельного запуска не должны содержать друг друга. До записи проверяются все входные статьи, уникальность их article_id и читаемость/структура существующего article_index.json. Это частичная проверка контрактов, полная JSON Schema пока не исполняется. `article_archive.json` содержит действия, URL и ссылки; в `article_index.json` добавляется archive_path. Старые карточки запуска сохранены для исторических ссылок.

Общий JSON I/O атомарен (flush/fsync + hard link без замены); изменяемые отчёты заменяются только явно. SQLite-транзакции защищают конкурентные записи. После сбоя подхватывается уже записанный JSON; при утрате индекса основные ID/URL восстанавливаются из файлов. `.archive.sqlite3` также хранит дополнительные наблюдения, которых нет в основном JSON, поэтому это постоянные данные, а не временный кэш. Архив, индекс, data/ и .tmp/ исключены из Git.
