# Research по новым событиям

Текущий fast-план v1.1: источники → открытый поиск событий → уточнения по доказанным пробелам. Семь разделов остаются классификацией выпуска; поиск сосредоточен на трёх направлениях. Новые запуски включают анонсы, пилоты, beta и выход на рынок; фичи включают AI, безопасность и тарифы; маркетинг включает кампании, креатив, коллаборации, амбассадоров, активации и значимые брендованные исследования.

## Данные и порядок

1. init-run фиксирует новые версии configs. Не подменять старые снимки; для нового маршрута создавать новый запуск. Старый снимок без research_policy доступен только через exhaustive для сравнения.
2. source_indexes проверяются по одному разу на нейтральный URL. Сначала официальные newsroom/IR, затем другие официальные источники, затем GDI, TechCrunch, Dating Industry Insights, 36Kr, «Ведомости». Для tapple используется https://www.tapple.co.jp/news/, для Coffee Meets Bagel — https://www.coffeemeetsbagel.com/press. Списки датированных публикаций проверены 16 ноября 2026 веб-инструментом. Общий отчёт может дать несколько событий и брендов. Шаблон source_indexes[].review содержит feed_available, checked_through, end_of_feed, next_page_url и evidence_urls; фактические проверки записываются в raw/source_reviews.jsonl. Период закрывается после достижения его начала или доказанного конца ленты. Фиксировать, что действительно проверено до начала выбранного периода, а не только открыт URL.
3. first_pass — открытые короткие запросы без брендов по трём направлениям на RU/EN/ZH/JA. Дополнительные external_discovery ищут интервью и результаты экспериментов на RU/EN. Для компаний всех рынков есть условные external_company на основном языке; выбор формулировок также поддерживает ZH/JA. Эти обращения находят неизвестных игроков и события вне каталога. Отсутствие публикаций нужного типа за период допустимо. Точные тексты и число задач берутся из плана, не из документации.
4. if_gap — резерв. Выполнять при конкретном пробеле компании/языка/направления источника либо сигнале события. Использовать одно имя, необходимый квалификатор, одно действие/механику. Другой алиас/синоним — следующий шаг при пробеле. На компанию/язык предусмотрено одно условное уточнение с действием. Подсказки golden set и 14 моделей остаются словарём снимка, а не заранее развёрнутыми задачами. Нужный запрос создаётся через discovery.queries.build_followup_query по observed intent, языку и term_index. Доступны изменения продукта, ограничения, отключения/откаты, редизайн, тарифы, миграции, интервью, результаты экспериментов и раскрытия. Для известной компании используется company_id, для нового названия — company_name. Внешний запрос содержит исключения известных официальных доменов и запасной query_without_domain_exclusions для провайдера без -site. Следующий синоним выбирается по результату предыдущего обращения; фактические параметры и причина сохраняются. Весь резерв безусловно не исполнять.
5. Проверки: компания × предусмотренный язык и источник × три направления. Только query_id/URL, период и наблюдаемый результат закрывают ячейку; упоминание бренда этого не доказывает. Для Liangpei первичен китайский, для Pairs/tapple — японский. Пропуски видны. Дополнительная очередь финансов/рисков/моделей учитывается отдельно.

Тематические подсказки задаёт queries.company_event_hints. Они расширяют поиск при пробеле/сигнале, не требуют повторить старую новость в новом периоде. Каталог 27 компаний сохраняется, включая Badoo, Мамбу, Twinby и VK Знакомства, которых нет отдельными примерами в golden set.

Опрос World/Harris Poll не заменяет эталон запуска рекламной кампании. В golden_set.marketing_reference_cases добавлены три отдельно проверенных исторических примера: [Tinder / It Starts With a Swipe](https://www.tinderpressroom.com/2023-02-27-TINDER-REDEFINES-EXPECTATIONS-WITH-NEW-BRAND-CAMPAIGN-THAT-CELEBRATES-GEN-ZS-AUTHENTIC,-FLUID-AND-BEAUTIFUL-CONNECTIONS) — новая брендовая кампания; [Hinge / Hingie Afterlife](https://hinge.co/newsroom/hingie-afterlife-2024) — новая волна креатива существующей платформы; [Bumble × LÕK](https://loksports.com/en/lokblog/press-release-bumble-y-lok-n21) — коллаборация с будущими офлайн-активациями. Даты, этапы и поисковые ориентиры сохранены в конфиге. Это исторические reference-примеры, а не новости текущего окна; сообщения подтверждают анонс/план, не независимую эффективность. Synthetic selection_checks остаются отдельными проверками фильтра и не выдаются за реальные новости или исходные user-accepted cases.

## Ранний отсев и запись события

Исключать по типу материала: сравнения сервисов; лучшие приложения/рейтинги; советы по выбору и использованию; обзоры без нового события; старое событие в новой перепечатке. Явные заголовки можно отсеять до загрузки через screen_candidate из discovery/screening.py, передав candidate_filter снимка queries.json. Функция возвращает только excluded либо needs_review: она не доказывает новизну, дату или пригодность. Доказанная смысловая классификация material_type имеет приоритет перед эвристикой заголовка.

Не использовать глобальные -best/-review/-survey. Кампания с подобным словом в названии требует проверки текста. Неясный материал загружается и проверяется; фича из сравнения ищется отдельным сообщением, само сравнение отклоняется. URL/title и reason сохраняются в raw/rejected_materials.jsonl, полный текст явного шума не нужен.

Рабочая заметка raw/event_candidates.jsonl: actor, company_ids, what_changed, mechanism, markets_or_audience, launch_stage, published_at, source_url, evidence, status. Неизвестное — null/unknown и needs_review. Дата публикации и новый факт подтверждаются текстом, dateModified не подходит. Для внешних рисков company_ids может быть пустым. Эти заметки не меняют контракты Article/event: подходящие статьи сохраняются прежним архивом, полноценные события формируются на этапе отбора.

## Проверка результата

Локальные тесты проверяют направленность запросов, отдельный поиск кампаний, локальные языки, полноту связей query_id, сохранность каталога, консервативность фильтра и согласованность конфигов. Живой контроль отдельно измеряет сохранённые релевантные события golden set, подтверждённые запуски/фичи/кампании, исключённые сравнения/рейтинги, загрузки шума, время до архива/отчёта и незакрытые проверки. Сокращение поисков без этих измерений не доказывает качество или ускорение. Сеть, платный API, доставка и автономный исполнитель этим изменением не добавляются.
